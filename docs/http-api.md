# HTTP API

The admin server (`:7990`) answers from the route tables in
`caravan/admin/routes.py`. The same API is described as OpenAPI 3.1 at
**`GET /openapi.json`** — open without sign-in, like `/health`, and built from
the tables and the handlers' docstrings when the controller starts
(`caravan/admin/api_spec.py`). The endpoint list below is rendered from that
document: to change a line, change the handler's docstring and run
`python3 scripts/check_api_spec.py --write`. CI fails when the page, the
document and the code disagree. (Until 2026-09-29 this list was written by
hand, and it had fallen 16 paths behind the 164 it covered.)

Everything is JSON unless noted; errors come back as `{"error": "..."}` with the
status the handler chose (`AppError`), or 500 — except that many handlers
answer a refusal as 200 with `{"ok": false, "error": "..."}`, and their lines
below say so. Arguments travel as query strings on GET/DELETE and as a JSON
body on POST.

The description is level 1: what each operation does, the query parameters
and top-level body fields its code reads (read off the code, so a handler
that passes its query or body on whole is marked "…" — it may read more),
the content types it answers with, and who may call it. Field types and the
shapes of answers are not described yet.

## Dispatch

- Prefix routes are checked first, in order: `/api/monitor/{kind}`, `/js/{file}`, `/css/{file}`.
- POST reads the body before the path lookup. An empty body is `{}`; a body
  that is not a JSON object is refused with 400 — on an unknown path too —
  and a chunked one with 411.
- Every verb answers with the status an `AppError` carries.
- Unknown paths → `{"error": "Not found"}` 404.
- New routes register with `@_route(TABLE, "/path", …)`; duplicate registration
  fails at import time. A new route needs a docstring: its first line is the
  summary (at most 90 characters), the rest is its description.

## Sign-in

Sign-in is off until the first account exists (see [security.md](security.md));
`GET /health` says `authRequired`. Then `POST /api/auth/login
{username, password}` sets the `caravan_session` cookie, and every route needs
it except the open ones (`open` below: the login and setup pages and their two
POSTs, `/api/auth/me`, `/health`, `/openapi.json`, the favicons). A viewer
account may call every GET and log out (`any account` below); everything else
needs an admin account (`admin`). The machine endpoints (`fleet token` below: model downloads and cell
assets for the scouts, their heartbeat) take the fleet token in
`X-Caravan-Token` instead; `/metrics` takes it as a Bearer token too, or a
session. Who may call what is one rule, `caravan/admin/route_access.py`, read
by the guard and by `/openapi.json` alike.

## Proxy daemon surface (per route port)

Each enabled route binds its own port (`CARAVAN_PROXY_BASE_PORT`, default `:23001+`; this fleet's historical routes sit at `:8101+`). The daemon is not a REST
API — it forwards whatever OpenAI-compatible traffic arrives:

| Method & path | Purpose |
|---|---|
| `GET /v1/models` | Fast path: answered from the upstream's cached model list. |
| anything else | Proxied through the full lifecycle (queue → route → upstream → relay). See [backend-proxy.md](backend-proxy.md#request-lifecycle). |
