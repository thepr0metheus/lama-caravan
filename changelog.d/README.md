# Записи журнала изменений до выпуска

Каждый merge request кладёт сюда свою запись отдельным файлом. `CHANGELOG.md` он не трогает.

Зачем. Раньше каждый merge request дописывал запись в верх секции `## Unreleased` файла `CHANGELOG.md`.
Каждое слияние ссорило все остальные открытые merge request на одних и тех же строках: 7 ноября 2026 года
одиннадцать merge request, и каждый перед слиянием приходилось заново сливать с `main`. Отдельные файлы не
сталкиваются. Так же устроены towncrier, changesets и журнал самого GitLab.

## Как написать запись

1. Назовите файл `ГГГГ-ММ-ДД-слова-ветки.md`: день, когда пишете, и слова имени ветки без приставки.
   Для ветки `feat/delivery-lock` — `2026-11-07-delivery-lock.md`. В имени только строчные латинские буквы,
   цифры и `-`.
2. Напишите запись так же, как писали в `CHANGELOG.md`: пункт списка с `- ` в начале, по-русски, с днём в
   скобках. Пунктов может быть несколько. Заголовков `#` не пишите.
3. Положите файл в тот же merge request, что и правку.

Прочитать все записи подряд, новые сверху:

```sh
python3 scripts/changelog.py show
```

## Выпуск

```sh
python3 scripts/changelog.py release <версия>
```

Записи встают в `CHANGELOG.md` секцией `## <версия> — <день>` под `## Unreleased`, новые сверху (по дню и имени
файла), а их файлы удаляются. Коммит выпуска идёт через merge request, как любой другой.

Гвард `scripts/check_changelog_fragments.py` краснеет, если запись снова легла в `CHANGELOG.md` или файл здесь
назван не по образцу.
